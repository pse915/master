# srbtimetable2026 — React + Streamlit + Google Sheets 시험감독 시스템 완전 흡수통합 개발 프롬프트

## 0. 개발 목표

당신은 Streamlit, React, TypeScript, Python, Google Apps Script, Google Sheets 및 학교 업무 시스템의 전문 풀스택 개발자이자 테스트 엔지니어다.

현재 운영 중인 학교 시간표 웹앱에 별도로 개발된 Google Apps Script 기반 시험감독 자동 배정 시스템을 완전히 흡수통합하라.

**이번 작업은 두 웹앱을 단순히 링크하거나 iframe으로 연결하는 것이 아니라, Google Apps Script의 비즈니스 로직을 Python으로 이전하고 기존 React UI에 시험감독 관리 기능을 추가하는 것이다.**

기존 시간표 웹앱의 모든 기능을 보존하고, 시험감독 시스템의 실제 작동 기능 역시 빠짐없이 이전하라.

### 기준 시스템 A — 기존 시간표 웹앱

- GitHub: https://github.com/pse915/srbtimetable2026
- 운영 주소: https://srbtimetable2026.streamlit.app/
- 운영 진입점: `timetable_app2.py`
- 기존 관리자 계정 ID: `pse915`
- 프론트엔드: React
- 백엔드: Python + Streamlit
- 데이터 저장: Google Sheets
- 인증 및 API 키: 기존 Streamlit Secrets 활용

### 기준 시스템 B — 시험감독 자동 배정

첨부된 다음 두 파일을 기준으로 한다.

- `Code.gs`: Google Apps Script 백엔드
- `Index.html`: HTML, CSS, JavaScript 프론트엔드

실제 첨부된 전체 소스를 분석해야 한다.

기존 Streamlit React 컴포넌트 안에 시험감독 모듈을 추가한다.

기존 시간표 React 화면과 시험감독 React 화면은 같은 디자인 시스템, 메뉴와 사용자 세션을 공유한다.

### 3.2 단일 Python 백엔드

기존 `Application` 객체를 중심으로 시험감독 기능을 연결한다.

시험감독 작업은 별도 서비스 모듈로 분리하고 기존 시간표 비즈니스 로직과 혼합하지 않는다.

기존 `dispatch()`와 `snapshot()` 계약을 보존한다.

시험감독 요청은 `exam.` 네임스페이스를 사용하여 기존 요청 이름과 충돌하지 않게 한다.

예시:

```text

exam.save_schedule
exam.get_teachers
exam.save_teachers

exam.generate
exam.improve
exam.update_assignment
exam.swap_assignment
exam.swap_role

exam.fairness
exam.optimization_report
exam.history
exam.print_schedule
```

최종 API 명세는 실제 Apps Script 함수와 현재 UI 호출을 전수 대조하여 결정한다.

이름만 있는 미구현 API는 만들지 않는다.

## 5. 관리자 로그인 및 권한 통합

기존 시간표 관리자 로그인 시스템을 재사용한다.

### 5.1 관리자 계정

기존 관리자 ID `pse915`로 로그인한 사용자는 서버 측 관리자 권한 검증을 통과하면 시험감독의 관리자 기능을 사용할 수 있어야 한다.

관리자 ID 문자열만으로 권한을 부여하거나 새 코드에 비밀번호를 하드코딩하지 않는다.

기존 인증 데이터와 서버 측 권한 검증을 사용한다.

### 5.2 이중 로그인 제거

Streamlit 로그인 후 별도의 시험감독 관리자 로그인을 요구하지 않는다.

기존 Streamlit 인증 상태를 Python 백엔드에서 검증하고 시험감독 권한에 연결한다.

기존 사용자 계정과 비밀번호를 변경하지 않는다.

### 5.3 권한 구분

관리자와 일반교사를 구분한다.

관리자는 시험일정, 교사 명단, 배정, 공정성 및 저장 기능을 사용할 수 있다.

일반교사는 기존 시간표 권한을 그대로 유지하며, 승인된 시험감독 조회 기능만 사용할 수 있다.

교사 자신의 감독 배정 조회와 전체 감독 시간표 조회 권한은 관리자가 설정할 수 있도록 한다.

기존 사용자별 허용 탭 설정과 충돌하지 않아야 한다.

### 5.4 첨부 코드 인증 취약점 수정

첨부 `Code.gs`에는 실질적인 권한 검사를 생략하는 관리자 인증 코드가 존재한다.

이 코드를 그대로 Python으로 복사하지 않는다.

다음 사항을 준수한다.

- 모든 읽기·쓰기 API에서 권한 검사
- 관리자 전용 함수는 관리자만 호출
- 화면 숨김만으로 권한을 처리하지 않음
- 사용자 ID 위조 방지
- 다른 사용자의 세션 상태 혼입 방지
- 로그아웃 시 시험감독 작업 상태 정리
- 서버 측에서 사용자 역할 재검증
- 이름이나 이메일 문자열만으로 본인 인증했다고 판단하지 않음

권한 변경 전후의 기능 동작을 모두 테스트한다.

원본에 있는 데이터를 임의로 변경하거나 삭제하지 않는다.

### 6.2 기존 시간표 시트와 충돌 방지

기존 Streamlit 시간표 시스템에서 사용하는 스프레드시트와 시험감독 스프레드시트를 독립적인 저장 영역으로 관리한다.

이름이 같은 워크시트가 있다는 이유로 다른 시스템의 시트를 덮어쓰면 안 된다.

### 6.3 Streamlit에서 시트 연결

Google Apps Script의 `SpreadsheetApp.getActiveSpreadsheet()`는 Python에서 그대로 사용할 수 없다는 점을 반영한다.

대신 기존 Streamlit의 Google 서비스 계정 인증을 재사용한다.

관리자가 시험감독 설정 화면에서 Google Sheets 주소를 등록하면 다음을 수행한다.

1. 주소에서 스프레드시트 ID 추출
2. 서비스 계정의 접근 권한 검증
3. 시험감독 워크시트와 헤더 검사
4. 기존 데이터 무결성 검증
5. 연결 정보 서버 측 저장
6. 연결된 시트 이름과 상태 표시

연결 정보는 기존 서버 측 설정 저장 구조를 우선 재사용하고, 영속성이 필요한 경우 관리자만 수정할 수 있는 별도 설정 저장소를 안전하게 추가한다.

Streamlit 세션이나 로컬 파일에만 저장해서 서버 재시작 후 연결 정보가 사라지는 문제가 없어야 한다.

관리자가 `app.py`, `Code.gs` 또는 스크립트 속성을 직접 수정하도록 요구하지 않는다.

### 6.4 사본 지원

학교별로 Google Sheets를 복사한 경우, 관리자가 새 사본을 선택하면 해당 사본의 데이터로 연결을 전환할 수 있어야 한다.

웹앱은 등록된 시트 ID와 실제 데이터 시트를 검사해야 한다.

다른 학교의 시트와 혼동하지 않도록 연결 대상을 명확하게 표시한다.

Google Apps Script와 달리 Streamlit에는 현재 열려 있는 Google Sheets의 자동 바인딩 개념이 없으므로, 아무 설정 없이 사본을 자동 식별한다고 가정하지 않는다.

### 6.5 양쪽 앱의 동시 운영

기존 Google Apps Script 웹앱도 독립적으로 계속 작동할 수 있어야 한다.

Streamlit 통합본은 시험감독 원본과 같은 Google Sheets를 사용하는 경우가 있으므로, 다음을 구현하라.

- 최신 데이터 재조회
- 저장 전 변경 여부 확인
- 충돌 시 저장 중지
- 중복 배정 방지
- 저장 이력 보존
- 부분 저장 오류 복구
- 스키마 마이그레이션 충돌 방지

단, Apps Script와 Streamlit에서 서로 다른 잠금 서비스를 사용하므로 LockService와 Python 프로세스 잠금만으로 완전한 교차 시스템 동시성 제어가 되는 것으로 간주하지 않는다.

공유 revision 또는 CAS 방식 등 양쪽에서 동일하게 검증 가능한 저장 프로토콜을 설계하라.

그 프로토콜을 실제 검증하기 전에는 같은 시트에 대한 양쪽 동시 쓰기를 허용하지 않는다.

## 7. 시험감독 자동 배정 엔진 Python 이전

이번 개발의 핵심이다.

Apps Script의 배정 알고리즘을 단순화하거나 다른 알고리즘으로 대체하지 않는다.

### 7.1 필수 배정 규칙

원본 코드의 실제 규칙을 기준으로 다음 조건을 유지한다.

- 시험과목과 감독교사 담당 교과의 충돌 방지
- 교사의 담임학급 감독 제한
- 날짜별 감독 불가 시간 반영
- 교사별 과목 및 상치교과 반영
- 겸임교사 일정 반영
- 교사감독규칙 반영
- 정감독·부감독 구분
- 자습시간 감독 처리
- 교사별 중복 배정 방지
- 연속 감독 관련 조건
- 학년 관련 우대 조건
- 감독 횟수 균형
- 역할별 공정성

단, 위 규칙의 정확한 우선순위, 예외 및 적용 범위는 반드시 원본 `Code.gs`를 기준으로 한다.

### 7.2 날짜·교시 선택

원본 시스템의 1~5일차, 1~5교시 구조 및 설정 가능한 운영 범위를 보존한다.

요일이나 교시가 일부만 설정되어도 작동해야 한다.

자습시간이 삽입된 경우 시험감독과 자습감독의 배정 방식이 정확하게 적용되어야 한다.

### 7.3 최적화 기능

다음 기능의 실제 구현을 분석하고 동등하게 이전한다.

- `generate`
- `improve`
- `fairness`
- `optimizationReport`
- `compareGradeBonus`
- `availabilityReport`

최적화 프리셋, 학년별 가중치, 역할별 업무강도 및 연속 감독 회피 설정을 보존한다.

원본의 제약 우선순위를 변경하지 않는다.

필수 조건과 소프트 제약조건을 구분한다.

소프트 제약 개선을 위해 필수 조건을 위반해서는 안 된다.

### 7.4 수동 수정

다음 작업을 구현한다.

- 감독교사 직접 변경
- 감독교사 교환
- 정감독·부감독 교환
- 특정 교사 제외
- 배정 수정 후 공정성 재평가
- 수정 내용 저장

원본 API 중 `update`, `swap`, `roleSwap`에 해당하는 동작을 정확하게 이전한다.

### 7.5 배정 결과 유효성 검사

자동 배정 결과를 저장하기 전에 모든 필수 조건을 검사한다.

원본 `fullValidate_()`의 검증 항목을 누락하지 않는다.

조건을 만족하는 해가 없을 때는 잘못된 배정을 저장하지 않는다.

대신 다음 내용을 안내한다.

- 배정할 수 없는 학급·교시
- 적용된 제약조건
- 충돌한 교사
- 필요한 조정 사항

### 7.6 원본과의 결과 비교

단순히 배정 결과가 생성되는지만 확인하지 않는다.

동일 입력과 동일 랜덤 시드 또는 재현 가능한 조건에서 다음을 비교한다.

- 배정 가능 여부
- 필수 제약 위반 수
- 정감독 횟수
- 부감독 횟수
- 자습감독 횟수
- 교사별 업무강도
- 연속 감독 분포
- 공정성 평가
- 최적화 결과

원본이 비결정적인 알고리즘인 경우 결과가 완전히 같지 않더라도 허용할 수 있으나, 제약 및 평가 기준의 동등성이 검증되어야 한다.

## 8. 시험감독 프론트엔드 완전 이전

첨부된 `Index.html`을 React 컴포넌트로 전환한다.

기존 HTML 코드를 통째로 React 안에 삽입하는 방식은 사용하지 않는다.

기능 단위로 컴포넌트를 분리한다.

### 주요 화면

**교사별 감독 조회**

교사 이름 검색, 개인 감독 일정 확인 및 결과 조회를 구현한다.

**전체 감독 시간표**

학년, 날짜, 교시, 학급을 기준으로 감독 배정을 표시한다.

**시험일정 설정**

시험일, 학년, 학급, 교시, 과목, 자습시간 등 원본의 입력 구조를 유지한다.

**교사 명단 및 조건**

배정인원, 담당 교과, 담임학급, 상치교과, 감독 가능 역할 및 감독 불가 조건을 관리한다.

**수업·겸임교사 일정**

교사시간표, 겸임교사설정, 교사감독규칙과 관련된 입력 및 수정 기능을 유지한다.

**자동 배정**

자동 생성, 개선, 결과 확인, 직접 수정 및 저장을 구현한다.

**공정성 분석**

교사별 감독 횟수, 역할별 분포 및 원본의 공정성 평가를 시각화한다.

**기록·인쇄**

현재 원본에서 작동하는 이력 조회, 저장된 버전 조회 및 출력 기능을 이전한다.

이전 버전의 비활성화된 확정·잠금 기능을 구현 완료된 것으로 간주하지 않는다. 실제 복구가 필요하다면 별도 변경사항으로 명시한다.

### 프론트엔드 상태 관리

다음 동작을 보존한다.

- 저장 전 변경사항 표시
- 저장 실패 시 입력값 보존
- 중복 요청 차단
- 로딩 상태 표시
- API 응답 순서 검증
- 오류 메시지 표시
- 상태 새로고침
- 인쇄 시 메뉴 및 버튼 숨김

## 9. 기존 시간표와 시험감독의 선택적 연동

두 프로그램을 하나로 통합하되, 처음부터 데이터를 강제로 합치지 않는다.

시험감독은 기존의 시험감독 Google Sheets만으로 독립 실행할 수 있어야 한다.

추가적으로 관리자가 선택하면 기존 시간표의 교사 정보나 수업시간표를 시험감독 설정에 반영하는 기능을 제공할 수 있다.

연동 기능은 다음 원칙을 따른다.

1. 기본값은 연동 OFF
2. 연동 방향을 명시
3. 변경 전 미리보기 제공
4. 교사 ID 및 학급 식별자 검증
5. 동명이인 확인
6. 기존 설정 덮어쓰기 전 승인
7. 오류 시 복원 가능
8. 기존 시간표 데이터의 역방향 수정 금지

현재 구현되지 않은 연동 기능 때문에 기존 시험감독 기능이 제한되면 안 된다.

## 10. 성능 최적화

기존 시간표 프로그램의 속도를 떨어뜨리지 않는다.

### 10.1 모듈 분리

시험감독 모듈의 무거운 데이터와 최적화 엔진은 필요한 때에만 로딩한다.

시험감독 메뉴를 열지 않은 사용자는 기존 시간표 기능에 대한 성능 저하를 체감하지 않아야 한다.

### 10.2 Google Sheets 요청 최적화

- 배치 읽기·쓰기 사용
- 동일 요청 내 데이터 중복 조회 최소화
- 불필요한 전체 시트 재조회 방지
- 읽기 캐시와 쓰기 후 무효화 구분
- 변경된 데이터만 안전하게 저장
- 저장 직후 데이터 무결성 확인

캐시가 다른 사용자에게 데이터나 권한을 누출하지 않게 한다.

### 10.3 배정 엔진 성능

Python 배정 엔진은 원본과 결과 동등성을 유지하면서 최적화한다.

- 후보 교사 사전 필터링
- 제약조건 계산 캐싱
- 증분 공정성 평가
- 중복 탐색 제거
- 실행시간 제한
- 작업 취소 및 오류 복구

배정 계산 도중 기존 시간표 데이터가 변경되거나 다른 사용자가 감독 명단을 수정하면 저장 전에 재검증해야 한다.

### 10.4 Streamlit 안정성

Streamlit Community Cloud의 메모리, 실행시간 및 재시작 특성을 고려한다.

서버 프로세스에만 중요한 데이터를 보관하지 않는다.

최적화가 길어지더라도 기존 React 컴포넌트가 흰 화면이 되거나 세션이 손상되지 않아야 한다.


설정된 경우 기존 E2E 테스트도 실행하고, 시험감독 기능에 대한 브라우저 테스트를 추가한다.

기존 `frontend/dist/`가 Streamlit 운영 실행에 필요한 구조이므로 소스와 빌드 결과가 일치하도록 관리한다.

빌드 결과를 확인하지 않고 개발 완료라고 보고하지 않는다.

## 12. 운영 중단 없는 배포 절차

운영 중인 Streamlit 웹앱을 우선 보호한다.

다음 순서를 준수한다.

### 1단계 — 원본 보존

- 현재 GitHub 커밋 SHA 기록
- 원본 브랜치 보존
- 현재 Secrets 설정 방식 기록
- Google Sheets 복제 백업
- 현재 동작 화면과 결과 기록

### 2단계 — 독립 개발

별도 통합 개발 브랜치에서 작업한다.

기존 main 및 운영 앱은 수정하지 않는다.

### 3단계 — 테스트 앱 구축

현재 저장소를 사용하는 별도의 Streamlit 테스트 배포를 구성한다.

진입점은 동일한 `timetable_app2.py`를 사용한다.

운영 데이터 대신 복제 Google Sheets를 연결한다.

### 4단계 — 전수 검증

기존 시간표와 시험감독 기능을 모두 검사한다.

모든 주요 테스트를 통과해야 한다.

### 5단계 — 운영 반영

관리자가 승인한 후 기존 main에 병합한다.

기존 Streamlit Cloud의 주소와 진입점을 그대로 사용한다.

### 6단계 — 배포 후 확인

실제 운영 환경에서 다음을 확인한다.

- 기존 관리자 로그인
- 기존 시간표 조회
- 기존 시간표 저장
- 시험감독 메뉴
- 시험감독 데이터 조회
- 허가된 시험감독 저장
- React 화면 안정성
- 권한 및 로그아웃
- Google Sheets 저장 결과

운영 환경에서 테스트 데이터를 임의 생성하거나 실제 배정을 훼손하지 않는다.

문제가 있으면 이전 GitHub 커밋과 백업 시트를 기준으로 복원할 수 있어야 한다.

## 13. 결과물 요구사항

설명이나 예시 코드만 제출하지 않는다.

다음 결과물을 제공한다.

### A. 실행 가능한 전체 통합 소스

기존 저장소의 파일을 보존하면서 시험감독 모듈이 추가된 전체 프로젝트를 제출한다.

### B. 변경된 파일 목록

신규 파일, 수정 파일, 삭제 파일을 구분한다.

각 파일의 변경 이유를 설명한다.

### C. 원본 기능 대응표

기존 시간표 및 시험감독 기능별 구현·검증 결과를 제공한다.

### D. 테스트 결과 보고서

테스트별 실제 실행 결과를 제공한다.

성공하지 않은 항목과 실행하지 못한 항목을 명확하게 표시한다.

### E. 배포 설명서

GitHub에 변경 파일을 업로드하는 방법과 기존 Streamlit Cloud를 유지하는 방법을 설명한다.

### F. 데이터 연결 설명서

기존 Google Sheets 서비스 계정과 시험감독 스프레드시트를 연결하는 방법을 관리자 관점에서 설명한다.

### G. 전체 ZIP

모든 코드를 포함한 실행 가능한 통합 프로젝트 ZIP을 제출한다.

단, 기존 저장소의 중요 파일을 제거하거나 임의로 바꾼 불완전한 ZIP은 인정하지 않는다.

## 14. 완료 판정 기준

다음 조건을 모두 만족해야 완료로 판정한다.

1. 기존 Streamlit URL이 유지된다.
2. `timetable_app2.py`가 진입점으로 유지된다.
3. 기존 React UI 구조가 유지된다.
4. 기존 관리자 계정이 유지된다.
5. 기존 시간표 기능이 정상 작동한다.
6. 시험감독 메뉴가 기존 React UI에 통합된다.
7. 시험감독의 원본 실사용 기능이 이전된다.
8. 자동 배정 제약조건이 보존된다.
9. 공정성 분석이 정상 작동한다.
10. 원본 Google Sheets 데이터가 보존된다.
11. 모든 관리자 API에 서버 측 권한 검사가 적용된다.
12. 기존 Google Apps Script 웹앱도 독립적으로 유지된다.
13. 추가 유료 호스팅이 필요하지 않다.
14. 통합 프로젝트의 빌드 및 테스트가 통과한다.
15. 운영 반영 전과 후의 기능 동등성이 확인된다.

**가장 중요한 최종 원칙**

이번 작업은 새로운 프로그램을 만드는 것이 아니라, 이미 운영 중인 두 개의 프로그램을 하나의 React + Streamlit 시스템으로 흡수통합하는 작업이다.

기존 기능을 축소하거나 단순화해서는 안 된다.

Google Apps Script에서 작동하던 시험감독 알고리즘은 Python에서 동등하게 작동해야 한다.

기존 Streamlit의 시간표 관리 기능은 어떠한 경우에도 시험감독 통합 때문에 손상되어서는 안 된다.

기능 100% 보존 여부는 실제 테스트 결과로 증명해야 하며, 검증하지 못한 기능을 완료했다고 보고하지 않는다.

개발이 끝나면 변경된 파일과 실행 가능한 전체 소스, 기능 대응표, 검증 결과 및 기존 Streamlit에 적용하는 정확한 방법을 제공하라.
